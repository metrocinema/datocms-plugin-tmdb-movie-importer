## Anti-Patterns Verdict

**LLM assessment:** The UI does not look like generic AI SaaS decoration. It is restrained, token-driven, and mostly respectful of DatoCMS. The remaining product-slop issue is strangeness without purpose: several custom controls appear inside a host environment that already has a strong component vocabulary. The stepper, review cards, checkboxes, image tiles, and fieldsets make the plugin feel like a plugin overlay rather than a fully native DatoCMS content-entry tool.

**Deterministic scan:** The Impeccable detector returned `[]` for `src/ui`. No rule hits, no file locations, and no false positives.

**Visual overlays:** No reliable user-visible overlay is available. The raw Vite plugin page at `http://127.0.0.1:5174/` fails before UI mount because `datocms-plugin-sdk` requires the DatoCMS iframe host. Overlaying that page would be misleading.

## Overall Impression

This is a safe and useful importer UI with clear editorial intent. It has moved a long way toward DatoCMS-native behavior by using `Canvas`, Dato styles, and core Dato form components. The biggest opportunity is not more styling; it is reducing “modal wizard friction” and making the review decisions feel like DatoCMS content editing rather than a separate mini-app.

## What's Working

- The import safety model is strong. The confirm step clearly says the plugin applies values to the unsaved form and does not save or publish the movie.
- The core DatoCMS React UI setup is correct: the app imports Dato styles and wraps screens in `Canvas`, while settings use `Form`, `Section`, `FieldHint`, `FieldError`, `FieldGroup`, `TextField`, and `Button`.
- The review structure is meaningful: selected movie summary, field changes, images, and people map to how an editor thinks about the task.

## Priority Issues

### [P1] Missing Back/Cancel controls in a high-stakes wizard

**Why it matters:** Editors need escape routes when they pick the wrong TMDB record or see a review they do not trust. Current Review and Confirm screens mostly move forward.

**Fix:** Add `Back` on Review and Confirm. Add Cancel/Close if the Dato modal context supports it. On Confirm, make `Back to review` visually secondary to `Apply to unsaved movie`.

**Suggested command:** `$impeccable harden src/ui`

### [P1] Hero image selection is hidden in backdrop selection order

**Why it matters:** “The first selected backdrop becomes Hero image” is fragile. Editors do not think in array order, and toggling backdrops can silently change which image goes to the Hero image field.

**Fix:** Make Hero image a first-class choice. Use a radio-style hero selector for one backdrop and checkboxes for Other images. Preserve the same import-plan shape by ordering the explicit hero image first internally.

**Suggested command:** `$impeccable clarify src/ui/ImagePicker.tsx`

### [P2] Custom controls still feel adjacent to DatoCMS, not fully native

**Why it matters:** DatoCMS React UI should carry the component vocabulary wherever practical. The current UI uses Dato primitives well, but custom steppers, cards, checkboxes, and image tiles are visually prominent enough to feel host-adjacent.

**Fix:** Keep custom presentation only where Dato lacks a component. Align custom checkbox/image selected, disabled, focus, and warning states with Dato tokens. Consider whether Dato sections can do more of the structural work.

**Suggested command:** `$impeccable polish src/ui`

### [P2] Disabled Continue does not explain the blocker near the action

**Why it matters:** Ambiguous people correctly block continuation, but the editor has to scan upward to find why. Disabled buttons without local explanation feel broken.

**Fix:** When unresolved people exist, show a compact warning above the footer action: “Resolve 2 people before continuing.” If feasible, link/focus the first unresolved person row.

**Suggested command:** `$impeccable clarify src/ui/ReviewStep.tsx`

### [P2] No standalone visual review harness

**Why it matters:** The Vite app cannot mount outside the DatoCMS iframe, so browser critique, accessibility scans, screenshots, and detector overlays cannot inspect the actual UI locally. That slows down UI quality work and makes regressions easier to miss.

**Fix:** Add a dev-only mock harness route or entry that renders `App`/`ImportModal` inside `Canvas` with fixture data, without connecting to live DatoCMS or TMDB.

**Suggested command:** `$impeccable audit src/ui`

## Persona Red Flags

**Jordan, first-time editor:** Jordan will understand “Find movie” and “Apply to unsaved movie,” but can get stuck when Continue is disabled because the explanation lives in the People section, not near the button.

**Alex, power editor:** Alex gets direct TMDB ID lookup, which is good. Repeated imports still feel click-heavy because field selection, image selection, and person choices have limited bulk patterns beyond “Select all changes.”

**Priya, cautious content lead:** Priya will appreciate the “does not save or publish” safety copy, but the partial-side-effect warning needs recovery instructions. She needs to know what to check in DatoCMS if a failure occurs after people or uploads are created.

## Minor Observations

- The repeated eyebrow “TMDB movie importer” appears on Search and Confirm but not Review. Make it shared or remove it.
- `fieldCountLabel` says “fields available,” but includes unavailable and unchanged rows. “mapped fields” or “selected changes” would be clearer.
- Search result overviews can become long and uneven; clamp or truncate them.
- The Year field converts non-empty input with `Number(value)`. Invalid numeric states could produce confusing searches.
- The hard-coded error boundary fallback in `main.tsx` uses raw color/font/padding rather than Dato tokens.
- Tests render UI components directly rather than inside `Canvas`, so they do not protect Canvas/theme integration.

## Questions to Consider

- What if the Review step had a sticky footer summarizing “4 fields, 1 person, 3 images selected” plus the current blocker?
- Should Hero image be a first-class decision instead of a side effect of backdrop order?
- Is immediate “Use movie” better for your editors, or do similar titles make a preview-selected step worth the extra click?
- Should side-effect warnings always include a recovery instruction?
